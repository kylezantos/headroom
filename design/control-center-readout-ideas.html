Ten Control Center readouts

Controls are the small buttons in Control Center. People can also put them in the Lock Screen’s bottom corners or on the Action button. Unlike widgets, Headroom can’t draw a control. It supplies three things: a symbol, a title and a value line, and the system draws the rest. So the design is mostly the symbol, because in most places the symbol is all anyone sees. Each idea below appears at the three Control Center sizes, on the Lock Screen, and on the Action button.

Three sizes, and the symbol is often aloneSmall shows only the symbol. Medium and large add the title and value line, and the same text appears at both sizes, so it has to fit medium: about 11 characters a line. The Lock Screen corners and the Action button also show only the symbol, plus a verb hint on the Action button (“Open Headroom”). So most designs here carry the number or level inside the symbol.
Symbols are pre-madeA control image must be an SF Symbol or a custom symbol built into the app; nothing can be drawn while the app runs. Every meter here is a set of pre-made symbols, one per level (every 5% by default), generated by a script from the same vessel geometry the widgets use (WidgetVesselGeometry).
One ink, so thickness carries the levelButtons get no colour; tint only colours a toggle while it’s on. The symbols are drawn in one ink, so a level has to read from shape: a thin track against a thick fill, solid liquid inside an outline. They don’t rely on two strengths of the same ink.
Freshness is the weak spotControls read the same synced data as the widgets, but they only refresh when tapped, when the Headroom app asks them to, or after a push notification. Headroom has no server, so it can’t send pushes. Whether the widget extension can refresh controls in the background needs a test. If it can’t, a control can show older numbers than the widgets, which is why 09 exists.
Every control does somethingA control is a button that runs an action. The readouts default to opening Headroom on that provider. The other actions are Check for new data (09) and Open the provider’s app (10). Adding a control asks which provider (promptsForUserConfiguration).
The value line needs a checkApple documents a value line for toggles (valueLabel). For buttons it only documents a title and symbol. If a button can’t show a second line, the number moves into the title; set Value line to “Title only” to see that. All ten ideas work for Claude, Codex, Grok and Cursor; 10 has one parity gap, noted on its card.

How they’d ship

Four controls in the gallery, not ten

Each control type shows up separately in the “Add a Control” gallery, so ten would be clutter. Ideas 01–05 differ only in their symbol, so they can be one Usage control with a Look option.

  • If you’d rather start small: Usage with the Mark + Vessel look (02), Lowest Limit (06), and Check for New Data (09). Together they cover one provider, all providers, and stale data.
  • New pieces: a control extension target, or adding controls to the iOS widget extension; generated symbol sets; one App Intent per action; a value provider that reads the shared app-group cache (WidgetSnapshotCache.appGroup()). The synced data’s format doesn’t change.
  • To test before planning: (1) whether a button can show a value line; (2) whether the widget extension can call ControlCenter.shared.reloadControls when new data arrives; (3) whether Control Center draws a custom symbol’s layers at two strengths (hierarchical rendering) or in one flat ink. Every design here is drawn flat, so the third only matters for polish.
