Popover and Settings refinements

Twelve things called out in the 9:46 walkthrough, each one drawn as options on the shipped tokens. Every mock is HTML and CSS at 1px = 1pt — the same numbers the SwiftUI views use, cited to file:line in the callouts. Meters are drawn by one renderer that takes the same parameters as MeterRecipe, so a cap or a flat end changes in every option at once. These are proposals, not decisions; nothing here is built unless it says it is.

Section 8 · t=7:44

Flat fill ends

In-app fills are clipped with cornerRadius = height/2, so both ends are rounded and the fill domes where it stops. The menu bar vessel does it differently: it clips to the capsule and fills a plain rect, so the base is rounded by the vessel and the top is dead flat (VesselGlyph.swift:58-71). That is the recipe being asked for.

7:44"Uhm, for the tube, we need to also make the cap on here not rounded, but flat. And that's even true for the solid."

8:04"Like, the end, within the pill, it's just weird when the top of the fill, regardless of which style it is, is rounded."

8:16"That should be flattened, just like we do in the menu bar version of it."

Resolution caveat. At 944px the menu bar pill is about 9px wide and the in-app tube about 4px. The rounded-versus-flat difference is legible in p12c but it is 2–3 pixels of evidence. The code confirms it independently — different clip recipes in MeterGauge.swift and VesselGlyph.swift — so the mocks below follow the code, not the frame.
