Refresh + Quit, and popover-wide loading

Fifteen matched Refresh / Quit pairs where Refresh turns into its own loader while a pass runs and then returns, plus twelve ways to show loading across the popover itself. Everything is live: click the buttons in each popover slice. Use the toolbar for light mode, Reduce Motion, ¼ speed, and slower or faster refreshes.

What the loop is allowed to doA refresh runs real work for 3–5s (print path) and up to 20–30s per account on the PTY fallback. Motion shows only while that work runs, so it tells the truth. Every loop travels or steps, so nothing pulses or breathes. When a pass finishes, the current cycle plays out before it stops. Nothing snaps back mid-turn.
Quit is quick and rareQuit is used rarely, so it can afford a short exit, but each one stays at 280ms or less. After that, terminate(nil) runs and the window fades on the same 120ms windowOut used today. ⌘R starts the same loading state as a click, so the loader reflects the work, not the keypress (R2M8).
Build-path tagsOverlay draws over the native bezel, the path the branch ships now (PA11b-safe). Mask animates a mask on the native bezel. Custom chrome replaces the bezel, so the upside-down rehost bug (PA11b) has to be solved again. Seam means the store has to expose a new signal.
Lenses applieddesign-motion-principles: Emil is the primary lens for a utility opened about 30 times a day, Jakub is secondary for polish, and Jhey only shapes the options marked wildcard. The house curve is (0.22,1,0.36,1), value motion never overshoots (M1A), and rolls go upward because time moves forward (M2A). DESIGN.md rules 4 and 6 hold: loaders use neutral ink only, and severity colours stay reserved for usage levels.

My picks, if you want a starting point

  1. V13 Stamp merge + P3 Focus. The most considered pair for this branch. The branch moved the freshness stamp next to Refresh, so the button can grow over the stamp and name the account being checked. It then shrinks back and leaves "Updated just now" exactly where that text already sits, so no text moves. P3 adds no loop at all: each card simply comes back into focus when its account lands. The catch is that V13 needs custom chrome and two store seams.
  2. V12 Upward drum. The lowest-risk upgrade. It uses SwiftUI's own .contentTransition(.push(from: .bottom)) over the native bezel and follows M2A. Pairs well with P1 or P2.
  3. V2 Per-account ticks + P2 Header rule. Choose this if honest progress matters more than character. Both need the same "completed of total" seam, so one piece of plumbing feeds both.
