Settings spacing audit

The Menu Bar arranger (262e1545), the Widgets providers row (same commit), and the per-account cadence lines (41744f11) arrived after the R2C19 spacing scale and drifted from it. The other panes still follow it. Each item shows a render, the convention it drifted from, and a mock built from the real tokens at 1px = 1pt. Mark every option Approve, Deny, or Discuss, then use Copy answers.

S1P1

Menu Bar tiles sit 10pt apart; every other pane uses 28

Where
SettingsPanes.swift:237 — the pane's one VStack spaces the pane title, the pinned tile, and the scrolling tile all at headerToContent (10).
Convention
SettingsMetrics.tileToTile = 28 (SettingsRows.swift:138), applied by SettingsPaneScaffold (SettingsPanes.swift:34). Menu Bar is the only pane that can't use the scaffold (its preview is pinned, #133), so it re-typed the scaffold and lost the second level.
Measured
Render: 10pt between the two Menu Bar tiles; 28pt between Theme and Meter Style in Appearance.
Suggestion

Nest the two tiles in their own VStack(spacing: SettingsMetrics.tileToTile) under the title, as the scaffold does. The scroll view's top edge moves 18pt lower, so scrolled content clips with a clear gap under the pinned tile instead of grazing it.

S2P1

Three caption styles in one pane

Where
SettingsPanes.swift:282–284 (“Menu bar preview”: 11 medium, primary ink), :306–308 (“Display”: 11 semibold secondary), :355–356, :448–449, :476–477 (“One automatic summary pill”, “Available Pills”, “Usage Shown in Each Pill”: 13 medium, primary ink).
Convention
Every other group caption in Settings is 11pt semibold secondary: Format / Shape / Fill (MeterStyleTile.swift:111–113) and Percentages / Account names (InAppDisplayTile.swift:91–93). Tile titles are the only 13–15pt headings inside a tile.
Measured
Render: “Available Pills” and “Usage Shown in Each Pill” read as a third heading level between the 15pt tile title and the 13pt rows, so the tile has four text tiers.
Suggestion

One caption style: 11pt semibold secondary for “Menu bar preview”, “Display”, “Available pills”, and “Usage shown in each pill”. “One automatic summary pill” stays 13pt medium because it's a state title, not a caption. See the full-pane mock under S3.

S3P2

Caption-to-content gap is 8 in some groups, 4 in another

Where
SettingsPanes.swift:277, :362, :447, :475 use spacing: 8; :305 uses labelToControl (4) for “Display”.
Convention
Caption above a swatch grid or list: 6pt (captionSpacing, MeterStyleTile.swift:41; InAppDisplayTile.swift:89). labelToControl (4) is for an inline row's label to its own help line.
Measured
Render: “Menu bar preview” → well ≈8pt, “Display” → cards ≈4pt, “Available Pills” → first row ≈8pt.
Suggestion

6pt from every caption to its content, 20pt between groups, 28pt between tiles. The mock shows the whole pane with S1–S5 applied. Turn on Show spacing to label every gap.

S4P2

The two provider lists run at different row pitches

Where
SettingsPanes.swift:450–462 (Available: 15pt logo + small button, VStack 8) and :478–501 (Usage: ResponsiveControlRow with a 22pt menu picker or 11pt text, VStack 8).
Convention
Rows in one tile share one pitch. The Accounts rows use a fixed status column and a fixed trailing slot for this reason (AccountsSettingsTile.swift, “audit P2”).
Measured
Render: Available rows step 24pt. Usage rows step 28, 27, then 24pt, because Grok and Cursor show read-only text instead of a picker. The same four providers have logos in one list and not in the other.
Suggestion

Give every row a 24pt minimum height with 4pt between rows, so both lists step 28pt. Add the provider logo to the Usage rows so the same provider reads the same in both lists. Shown in the S3 mock.

S5P2

Display cards don't use the Settings swatch shell

Where
SettingsPanes.swift:327–338 — a bare pill, left-aligned 11pt title and 10pt detail, padding(8), VStack(spacing: 6).
Convention
Every other swatch (Theme, Format, Shape, Fill, Percentages, Account names) puts its specimen in a recessed r6 well, then 5pt, then a centered 10.5pt medium label, with 5pt padding (MeterStyleTile.swift:258–274; InAppDisplayTile.swift:181–195). The r11 selection ring is concentric only at that 5pt padding (SettingsRows.swift, R2B3).
Measured
Render: the Display cards are the only swatches without a well and with left-aligned text. At 8pt padding the r11 ring sits 3pt off concentric.
Option A

Full swatch shell: pill centered in a 36pt well, one centered label. The detail line is dropped because the help line under the grid already says it.

Widgets: the new providers row splits a switch from its sub-option

Where
WidgetSettingsSection.swift:18–58 — “Widget providers” and its help were added inside the 8pt group between “Share data with widgets” and its dependent Spark checkbox.
Convention
PB4 (the comment at WidgetSettingsSection.swift:14–17): the Spark checkbox is a sub-option of widget export and nests directly under it. A row with its help uses labelToControl (4); sibling groups use groupToGroup (20).
Measured
Render: row → its help ≈25pt baseline-to-baseline vs ≈19.5pt for “Share data”, because the help sits 8pt under a taller menu control. The Spark checkbox now follows the providers help, so it reads as a providers option.
Option A

Three groups: [Share data + help + Spark checkbox] · 20 · [Widget providers + help at 4] · 20 · [Sync]. The help also links back to the Menu Bar pane again (PB8 did this before the arranger; SettingsHelpText(attributed:) is still there, now unused).

S7P3

General: cadence lines stack as extra fine-print paragraphs

Where
SettingsPanes.swift:101–105 — the long refresh help plus one SettingsHelpText per stretched provider, each 4pt apart.
Convention
R2B2: one help block under a control, not several 4pt-separated paragraphs. The help copy also uses internal terms (“CLI-probed”, “stays idle at least half the time”).
Measured
Render (no stretched providers): two lines of help. Each stretched provider adds a line like “Claude: 5 min chosen · about 9 min effective · 6 accounts” (LaneSchedule.swift:314), so two stretched providers make four stacked lines of 11pt grey text. That state isn't in the render harness; the mock is drawn from the code with example numbers.
Option A

Short help, then a compact two-column cadence list at 6pt, then one plain reason line.
