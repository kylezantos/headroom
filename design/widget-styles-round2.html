By size lines up every small, then every medium, then every large, so you compare the styles directly. By style shows each one as a family. Every widget has its own comment box, and the same box appears in both views. Each style also gets a verdict and a “keep as a selectable style” tick at the bottom.

If these become user-selectable styles: WidgetKit lets a widget carry its own options. Users long-press (iPhone) or right-click (Mac) → Edit Widget and pick a style for that one widget. That means no Settings UI and no change to the shared widget data, and two widgets on one desktop can use different styles. Your popover meter style (MeterStyle) isn’t sent to widgets today, so this keeps the two independent unless you want them linked.

Still not tokens. Each style would add these to WidgetTypeScale / WidgetMetrics, per DESIGN.md rule 2:

  • Hero numerals (30–50pt; the ladder stops at 18). All four styles need one or two.
  • Vessel at widget scale (02): wall width ≈ 7% of width, and it reuses tertiaryText for the wall. The menu-bar vessel’s colours come from MenuBarPalette, which widgets can’t use.
  • Liquid wash (15): fill 30% → 12% alpha with a 70% top edge. It needs its own tinted-mode rule.
  • Rail thickness (19): 3–4pt under a 7–10pt parent.

One gap from DESIGN.md is worth knowing: the popover has no named type ramp, so “popover language” means matching its literals, not a token set. Widgets do have one (above).
