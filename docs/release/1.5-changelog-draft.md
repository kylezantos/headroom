# Headroom 1.5 — changelog draft

Prepared October 2, 2026; updated October 4, 2026. Unreleased. Proposed build **35** for both Mac and iPhone (34 is reserved for the CloudKit spike's TestFlight upload) (see `1.5-release-checklist.md`). Inventory covers 1.4.1 build 33 (`042c8213`) through remote main `37a610c2` (PR #159), plus PR #160 (open). Main still carries 1.4.1/33 metadata. The iPhone redesign is in draft PR #161 and is **not** in this changelog yet. Add it when that PR merges.

## Tweet draft

Headroom 1.5 is almost here: arrange your menu bar, choose the limits you track, get reminders before unused usage resets, see Codex banked resets and both Cursor pools. Plus smarter multi-account refreshes, clearer progress, and a whole lot of polish.

## Full user-facing changelog

### Make the menu bar yours

- Add, remove, and reorder provider pills on a visual two-row shelf in Settings → Menu Bar. Drag between “In your menu bar” and “Not shown,” or use the add, remove, and move controls.
- Choose “Pills + percentages” or “Pills only,” with a preview that stays visible while editing. Keep an automatic summary if you prefer it.
- Choose the exact usage limit each pill follows: 5-hour, weekly, a reported model limit such as Fable or Codex Spark, either Cursor pool, or “Closest to limit.” Options reflect what the main account actually reports.
- See current values and reset information in each pill’s value menu. Configure a provider before adding its pill; turned-off providers link back to Accounts.
- If a chosen limit temporarily disappears, the pill follows the closest limit and returns to the saved choice when it is available again.
- Arrange menu-bar providers independently from app ordering and widget selection. Existing widget selections carry over, with provider controls in Widgets & iPhone.
- A subtle wave now indicates when a pill’s main account is being checked, including background refreshes. The displayed usage level stays accurate; Reduce Motion keeps the wave still.

### Use more of the subscription you already have

- New opt-in “use-it-up” notifications warn when a limit is approaching its reset with usage still available.
- Create multiple rules with your own lead time and percentage remaining. Defaults are one day before reset with at least 50% left, and six hours before with at least 25% left.
- Choose whether rules cover weekly limits, billing periods, and 5-hour windows. Weekly and billing-period limits are selected by default; 5-hour limits are optional.
- Reminders cover all providers and accounts, evaluate only fresh usage with a known reset, and remember delivered rules across app restarts to avoid repeated alerts for the same reset cycle.
- An optional Codex notification announces a newly banked reset. It does not notify on the initial count or on retained data from a failed refresh.
- Both notification features are off by default. Permission is requested when you enable one; Settings → Notifications includes permission recovery. Notifications are local to the Mac while Headroom is running.

### More useful provider details

- Codex’s plan badge now shows banked reset availability. Hover to see the count; it reveals the count when usage is critical and briefly when a higher count first appears. This is a display feature; it does not redeem resets.
- Cursor now shows separate **Cursor Models** and **Other Models** subscription pools instead of hiding both behind a single Included value. Both propagate to supported app, widget, and phone views; compact summaries default to the pool with less remaining, with a menu-bar override available.
- Claude’s “Weekly (Fable)” label is shortened to “Fable”; spoken labels and tooltips retain its weekly meaning. Codex model limits retain their period where needed to distinguish multiple windows.
- Popover accounts now show 5-hour usage first, then weekly or billing-period usage, then model limits. The Appearance preview and menu-bar limit picker follow the same order; widgets retain their weekly-first order.

### Better refreshes, especially with multiple accounts

- Account capacity increases from five to a tested envelope of **20 accounts per provider** for Claude, Codex, and Grok. Cursor remains single-account.
- Each account now has its own refresh schedule. Main accounts receive priority when overdue, temporary failures back off, and CLI polling is paced to limit sustained load. General settings explains when the effective refresh cadence stretches across many accounts.
- Manual refreshes take priority, and overlapping requests share work rather than launching duplicate probes. Refreshes recover cleanly when providers are turned off or account setup changes while work is pending.
- Background polling no longer presents itself as a user-started full refresh.
- The freshness timestamp moves beside Refresh: “Just now” or “2 min ago,” with “Checked…” when no data is live. The header is reserved for setup status.
- A manual refresh shows “Checking N accounts…” followed by each account’s result and progress, then returns to the timestamp. A stale result is named without a success checkmark.
- Refresh shows a spinner inside its button and disables during the operation; Refresh and Quit keep their widths.

### More reliable setup and recovery

- Claude sign-in now starts the official CLI authentication flow explicitly when supported, opens in Apple Terminal, and shows whether it is launching, waiting for sign-in, or confirming the result.
- Sign-in waiting state survives relaunches and allows a longer authentication window. “Show Terminal,” retry, cancellation, closed-Terminal, and timeout states give clearer recovery.
- “Sign Out & Set Up Again” works immediately after a connection succeeds, and pending Codex resets retain their intent while another login occupies the provider’s setup slot.
- Cursor is rediscovered after its CLI is installed while Headroom is already open. Usage capture waits for a complete panel and handles current prompt layouts more reliably.
- Cursor trust and external-tool approval screens receive explicit recovery handoffs. Usage probes do not type into those screens; trust is scoped to Headroom’s own empty probe workspace.
- Fixes Cursor browser login opening repeatedly during background refreshes when the CLI shows a signed-out screen. Headroom reports that sign-in is required instead.
- Grok and Cursor Terminal and clipboard setup paths now use the same resolved CLI and account environment as their usage probes.
- Prevents a second bundled Headroom instance from starting, including when a notification opens an installed copy while another copy is already running. This avoids duplicate polling and reminders.

### Choose a widget style

- Each Mac and iPhone widget can now pick one of four styles in **Edit Widget**. **Nested Meter** (the new default) shows every window with the main one on top. **Vessel Hero** puts a vessel beside a big number. **Tightest First** leads with whichever limit is lowest. **Liquid Level** fills the tile with a wash at each provider's level.
- A **Color** choice per widget: "Always colored" (default) or "Only when low", which keeps healthy meters neutral until a limit runs low.
- The API spend strip and the "Updated" footer appear on large widgets only.
- Widgets you already placed keep working and switch to the new default style. Settings › Widgets & iPhone previews the styles.

### Clearer loading

- Headroom now tells three things apart. Liquid sloshes while Headroom fetches, a drip marks a wait on you (such as a sign-in), and neutral ghosts mark readings that haven't arrived yet. Fresh readings print into place. A kept older value stays marked as older.
- Removing an account in Settings drains its row away. The refresh footer reports each account's result through both subscription and API spend checks.
- The menu bar prints its first live reading into place.

### Account problems are one clear action

- A signed-out or failing account shows one quiet row whose sentence is the button ("**Sign in** with the official Claude CLI"). This replaces a status line with two chips under it.
- A small leading icon shows where the click goes: Terminal for the official CLI, a globe for web pages, a refresh arrow for Check Now. Rows that leave Headroom show a ↗.

### About and updates

- Settings has a new **About** pane: the version, **Check for Updates…** with "Last checked …", a tip jar (through Stripe), and links to the maker's website, LinkedIn, X and GitHub.
- New **"Download and install updates automatically"** switch. A found update downloads in the background and installs when Headroom quits.

### Faster

- The popover opens at its final height in one frame. Before, the card list grew in over about 12 frames on every open.
- Scrolling the popover and opening Settings do far less work. With 20 accounts, a refresh while Settings is open went from about 100 ms of work to about 1 ms.

### Visual and interaction polish

- Settings has a consistent text hierarchy and spacing across panes, clearer group headings, and reorganized pill cards with the provider, preview, and value in distinct bands.
- Settings opens with a smoother handoff from the popover, without the initial position jump. Pane changes avoid overlapping text; keyboard navigation stays immediate.
- Pill cards follow the pointer, move between shelf rows, and settle smoothly. A new drag can interrupt a landing; move controls remain available through keyboard focus and accessibility actions.
- Appearance selection indicators move between swatches, meter-style changes resize the preview and surrounding content together, and menu-bar previews crossfade as the configuration changes.
- Fixes the Menu Bar settings pane clipping beneath the title bar. Widgets & iPhone previews all three widget sizes together.
- Popover cards scroll cleanly beneath the header without the top fade cutting through text. The bottom continuation fade remains.
- Corrects the popover’s double corner treatment, aligns API-spend titles with account titles, and improves spacing between API-spend rows.
- Meters show the real percentage immediately on opening, with a clearer fill arrival. Fresh/stale transitions no longer briefly double card height, and changing rows no longer animates a neighbouring row’s number.
- Full and continuous Micro meter fills gain rounded ends. Full Fade is softer; Full Segmented uses quieter empty cells and a slightly raised tip. Full Machined gains a recessed track, with quarter marks kept out of translucent fills.
- Provider logos are centred and optically balanced across the popover, Mac widgets, and iOS source.
- Setup waiting cards use a compact dot-matrix loading indicator. The later refresh redesign uses a native spinner in the Refresh button.
- Native footer buttons fix the cached-popover orientation regression when switching appearance.
- The DMG installer regains its dark background, gold arrows, and “DRAG TO INSTALL” treatment.

## Internal release notes and verification boundaries

- Release guidance now publishes through the independent `headroom-site` repository; signed installers and deltas live in the separate download archive. Public URLs are preserved. A design-system index and updated development guidance also landed.
- Rerun on 2026-10-04 on PR #160's branch (main `37a610c2` plus its fixes): `swift test` 1,256 tests in 92 suites pass; `HeadroomAppTests` 294 tests in 41 suites pass. Regenerate with `xcodegen generate` first, or the hosted suite misses its `--demo` argument and four demo-launch tests fail.
- The iOS build failure from shared setup types was fixed in #155 and the iOS parity branch builds with zero warnings on Xcode 27. The public App Store iPhone build (1.0, build 24) can't read any current Mac's snapshot, so the 1.5 iPhone release is what fixes it for existing phone users.
- Recorded acceptance gaps include real notification permission/banner behavior and live Codex zero-credit encoding. The single-instance guard also affects app tests while another bundled copy is open. Check these during release preparation; this inventory does not establish release readiness.
- No build, version bump, signing, publication, or announcement was performed for this draft.
