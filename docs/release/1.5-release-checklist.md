commands: `release-operations.md` (order and states), `website-dmg-release.md` (Mac),
`ios-app-review-testflight.md` (iPhone). Report each state separately. Never call a partial chain
"released".

## Finish line

1.5 is done when all of these are true:

- **Source ready.** One merged `main` commit carries 1.5 build 40 for every target.

- **TestFlight accepted.** A clean install passes the device checklist.
- **App Store submitted.** The 1.5 listing ("Headroom by Kyle Zantos") is submitted for review.

## Order to the finish line

1. Merge #160.
2. Land the Lock Screen PR (honolulu) on main, then merge main into the parity branch. Both
   touch `project.yml`, `DemoScreenshotData.swift`, `IOSCompanionView.swift` and the iOS widget
   extension. Do the merge once, early, and run the widget render sweep afterwards.
3. Kyle's device checks unblock the parity tail:
   - **P5.** The app/widget identity probe failed its same-account baseline on 2026-10-04. Rome
     investigates in code first and then asks for a short re-check. Cached loading stays off
     until it passes.
   - **U15 CloudKit spike.** Needs a signed Mac build and the iPhone. If checks 1–3 fail,
     reminders stay Mac-only (R29). That's already decided, not a new choice.
   - **U6 check-now spike.** If the Mac doesn't answer in the background, ship pull-to-re-read
     (already decided).
4. Parity units finish → U18 screenshots → U19 listing, privacy and docs → U20 integration and
   the merged-tree `ce-code-review` → PR → merge.
5. Release candidate on `main`: stamp 1.5 / 40 in `project.yml` (every macOS and iOS target),
   `xcodegen generate`, `swift test`, app tests, iOS UI tests,
   `bash Tests/ReleaseScripts/sparkle-release-notes-tests.sh`. Merge.
6. Mac: `HEADROOM_NOTARY_PROFILE=headroom-notary ./Scripts/release-app.sh` from that commit,
   then the headroom-site publish PR and `pnpm ship` (`website-dmg-release.md`).
7. iPhone: `HEADROOM_IOS_LAST_UPLOADED_BUILD=39 ./Scripts/release-ios-testflight.sh`, then
   upload with `HEADROOM_IOS_UPLOAD=1`.
8. Acceptance: Sparkle update from 1.4.1 on the test user/VM, TestFlight clean install on the
   iPhone, Track B reset fixtures (schema change), and the iPhone widget upgrade check (P2).
9. App Store Connect (P6): listing fields, Mac availability off, App Privacy answers,
   screenshots, submit.

## Release-day checks that need Kyle at the Mac

- **First signed build with the G2 certificate.** Run
  `HEADROOM_RELEASE_BUILD_ONLY=1 ./Scripts/release-app.sh` once while at the Mac. The new
  private key may show a Keychain prompt for `codesign`. #160 makes the scripts sign with the G2
  identity (SHA-1 `E9426A0D…`) instead of failing on the duplicate name.
- **CloudKit entitlement on the Mac (only if U16 ships).** The release archive uses automatic
  signing. Check that the exported app carries `iCloud.com.kylezantos.headroom`. The
  hand-made P3 Mac Direct profiles are in `islamabad-v1/.context/` if automatic signing doesn't
  pick it up.
- **Sparkle acceptance environment.** The dedicated test user or VM must have the public 1.4.1
  DMG installed *before* the 1.5 appcast goes live.
- **Notifications.** Real banners and the permission prompt only work in a built `Headroom.app`.
  Check them once on the candidate.
